# M1a delivery interface

Factory pages consume the five accepted P01 GET endpoints. URL filters are local to delivery views; the saved native harness and active project never filter factory work. Shared observations poll every five seconds while visible. Starting Load more synchronously retires old first-page requests and pauses that list until Refresh from start or a filter change. Rows, cursor and the pagination control remain in place; protected actions refresh details and mark paused lists dirty. Live inactive stores retire after subscription cleanup, including StrictMode resubscription. Paused lists keep their rows/cursor/dirty state across sibling detail navigation without active polling; Back restores the exact detail link focus, main scroll and table scroll. Activating another filter URL retires the prior paused list. Teams route reads retire stale preset/scope responses and bind controls immediately to the current URL.

Routes: `/`, `/work`, `/work/:workItemId`, `/repositories`, `/repositories/:scopeId`, `/teams`, `/teams/:teamId`, `/harnesses`, `/harnesses/:providerId`, and guarded `/harnesses/:providerId/:surface`. Canonical plans and Claude transcript details retain the route harness. `/agent-teams` redirects to Teams preserving query/hash; `/cc-bridge`, Agent Mail, Local projects and legacy native routes remain accessible. The checked-in native registry records provider/component/API/access mappings; runtime capabilities cannot create a missing adapter. Native provider scope is ready before mounting, without changing the saved preference. Codex inventories have separate nested read/write guards.

Safe context navigation selects a terminal only after a unique current team/slot/member/MCP-session match, and locks it read-only. Ambiguous/offline associations show filtered inspection. Mail context uses read endpoints with `sync=false` and never checks an agent inbox or acknowledges requests. Offline launch links retain the verified slot and require an explicit authenticated current plan review. Basic work details need no credential; protected history/retry reuse the existing per-tab operator helper. Retry always requires explicit destructive confirmation, including cached credentials and renewed authorization after a denial. A confirmation permits one mutation; navigating away retires pending authorization and stale results. Deferred owner release and reset-to-pending responses are shown without claiming a new dispatch. Unknown remedy eligibility links to the existing recovery surface; no browser agent-decision controls were added. Other mutations remain deferred to authoritative existing surfaces.

Accepted fixtures, source/review/full manifest hashes and explicit derived pagination scenarios are documented in `tests/fixtures/factory/PROVENANCE.md`. Native adapter fixtures freeze implemented M1a pages only. `tests/fixture-browser.mjs` serves built assets and isolated copied fixtures; run through `product-heavy` with `P02_EVIDENCE_DIR`. It records exact HEAD, fixture provenance, route/width screenshots, keyboard launch-review behavior, requests and runtime exceptions. It never connects to the running factory.

Verification: full Vitest suite and build via `product-heavy`, changed-file lint, full lint with an unchanged-blob proof for existing errors, and fixture browser checks at 360/768/1280. Exact-head B4 review, hosted CI and human feature merge are separate gates. This package does not establish M1a acceptance, pilot disposition, P03 authority or promotion/deployment.
