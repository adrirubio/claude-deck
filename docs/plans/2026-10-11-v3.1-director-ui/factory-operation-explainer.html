How a Claude Deck factory is operated

This page shows the simplified #506 proposal. The Director owns the GitHub backlog. The factory is the supervisor, the controller and the team working together on it. Deck code already finds most problems; v1 collects them on one card and adds a supervisor heartbeat. The supervisor runs outside the controller. It is optional during normal running and required for factory maintenance.

1The hierarchy of roles

The line of command runs Director → Leader → implementers and verifiers. The supervisor and the grooming helper are staff roles beside that line, and both are optional. Without a supervisor, the Leader reports directly to the Director. Each team has one Leader; the number of implementers and verifiers is the Director’s choice. Scope limits such as max_concurrent_dispatched cap concurrent work, not team size. The non-agent systems are not ranks: they enforce the hierarchy and keep the record.

Naming: Agent Mail already calls the human “Director”. In code, the authority interface keeps the name operator: the operator API and the operator token are the Director’s powers, and a supervisor uses them only under delegation. The UI will call the token the Director key (#518). An external agent such as OpenClaw takes the supervisor role. It is not a second Director.

2The factory and the parts around it

The factory has three parts: one AI-agent supervisor, one non-agent controller and an AI-agent team. The Director owns the factory. GitHub supplies the work and keeps the record.

What is in the factory?

Test: if the Director must start, stop, upgrade or repair a part, it is in the factory.

  • Supervisor — yes. The Director starts it and gives it delegation.
  • Deck controller — yes. Maintenance upgrades and repairs it.
  • Team — yes. Deck launches its sessions; the Director chooses the roster.
  • GitHub — no. It keeps running when the factory stops. It holds the Director’s backlog, and the result goes out there.
  • Director — no. The Director owns the factory and the backlog, and keeps the retained decisions.
  • Grooming helper — no. It is optional and works for the Director, not for the factory.

Kinds inside the factory

AI agents do the work that needs judgment: supervision, planning, implementation and review. Non-agent software does everything that a rule can do: dispatch, leases, Mail, attention signals and the maintenance operation. A human owns the backlog and makes the retained decisions. When something can be a rule, put it in the controller and not in an agent prompt.

3Two operating modes

In normal running, non-agent code finds problems and an agent or the human acts on them. Factory maintenance is the one mode that needs an agent outside the controller.

4Why the supervisor runs outside the controller

The supervisor is part of the factory, but it does not run inside the controller process. An agent inside the controller cannot do maintenance. In normal running it would repeat work that non-agent code and the Leader already do.

It cannot upgrade its own host

An upgrade stops the controller, proves termination and restarts it. An agent inside the controller stops when the controller stops.

A watchdog must not fail with the controller

If the controller stalls or crashes, an internal supervisor stops too, and nobody sees the failure.

No self-repairing controller

An internal agent with permission to change and deploy Deck makes the safety model much harder to understand.

6The optional supervisor heartbeat

The agent promises its next check. Non-agent code compares that promise with the clock. The agent never reports its own health.
