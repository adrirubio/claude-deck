Conversational Autonomy Setup — Guided Flow Mockups

Follow-on from 2026-07-03-autonomous-github-dispatch-ui-mockups.html. Explores an alternative, conversational entry point into the exact same TeamGithubScope/AgentTeamSlot configuration those form screens edit — the forms remain the source of truth and fallback path; this is a second way to arrive at the same data.

Decided going in: the interviewer is the same brain that later runs autonomous dispatch, in an interview mode rather than its dispatch loop. It inspects the team and target repo first and only asks what it can't infer. Answers are captured via inline widgets (buttons, chips, toggles), not free text, and nothing is written to the database until a final review/confirm step — mirroring the plan-hash confirmation pattern Deck already uses before launching a team.

"Edit in forms instead" is not a dead-end escape hatch — it's the seam between the two configuration paths. Clicking it doesn't discard the conversation; it opens the existing Add-scope/slot-editor screens pre-filled with exactly what's shown above, so a human who wants to double-check or tweak one number doesn't have to redo the conversation or trust a value they can't see edited live. This is the same "two paths, one schema" principle as the form mockups' API-vs-UI table (Screen 0 there) — the conversation is a third path into the same data, not a fourth kind of state.

Why this reply matters more than it looks: the brain doesn't just accept a correction — it checks whether the human's correction is actually about this conversation's scope before acting on it, and explains the schema fact (merge_policy is per-scope-entry, not team-wide) that resolves the apparent conflict. This mirrors a real pressure-test concern from the design spec: a conversational interface that silently reinterprets ambiguous instructions is worse than a form that forces the human to be in the right screen already. Jumping back a stage (rail step becomes "current" again) is a real navigation action, not a scripted reply — prior answers in later stages aren't discarded, only the stage being revisited is reopened for edits.
